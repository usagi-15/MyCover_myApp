# 『My Cover』展示アプリ 実装指示書（Claude Code 向け）

あなたはこの展示アプリの実装担当です。デザインは同梱の **ワイヤーフレームPDF（全15ページ）** に従い、画面の内容・操作はこの指示書に従ってください。
- 書かれていない事実（曲の長さ、サビの位置、ファイル名など）は作らず、`config` の値や `TODO:` にしてください。
- 下の「未決定事項」に関わる部分は、実装前に確認を取ってください。
- **フェーズごとに動く状態にしてから次へ進んでください。** 各フェーズの終わりに、動作確認の手順を短く説明してください。

---

## 0. 作品と体験の前提

- 作品：『My Cover』— 音楽コンテンツにおけるオーディエンス・ジャーニーの設計（武蔵野美術大学 デザイン情報学科3年 大石ゼミ／池田うさぎ）
- 展示：デザイン情報学科3年ゼミ展「滲む、響く。」 2026.12.3–12.5 9:00–18:00（最終日16:30まで）／鷹の台キャンパス9号館地下
- 楽曲：架空アーティストの1曲「**B7F**」（自作曲）。全員が同じ1曲を聴き、ジャケットだけが人によって変わる。
- 体験者は机の前に**立って**、キーボードとマウスで操作する。音は机上の**スピーカー**から出す。
- 画像生成は OpenAI の画像生成API（GPT Image）。鑑賞者の入力に、曲の世界観を記した**固定プロンプト**を組み合わせて送る。

## 2. 全体構成

```
[展示PC（Windows）]
  Flask サーバー（localhost）
   ├─ /desk      … 机のモニター用画面（Chrome ウィンドウ1）
   ├─ /display   … 大型モニター用画面（Chrome ウィンドウ2）
   ├─ /api/...   … 生成・状態同期・ログ
   └─ SQLite     … ローカル記録（研究データ・状態）
        │ 外向きHTTPS
        ├─→ OpenAI API（画像生成・入力のモデレーション）
        └─→ Supabase（ジャケット画像のアップロード、DB書き込み、カード番号とのひも付け）

[Supabase]
  ├─ Storage … ジャケット画像（jpeg、公開読み取り）
  └─ DB      … covers / cards / page_views テーブル

[GitHub Pages]
  ├─ スマホ用ページ（1枚のHTML。?t=<token> / ?c=<card_token> で表示を切り替え）
  └─ 楽曲MP3・フォントなどの静的ファイル

[鑑賞者のスマホ] 自分の回線で QR → スマホ用ページを開く
```

- `/desk` と `/display` は同じPCの2つのChromeウィンドウ。**状態はFlaskサーバーが一元管理**し、両画面はポーリング（例：500ms〜1秒間隔）で状態を取得する（追加ライブラリ不要のため）。
- 音声は**常に1つの画面だけが鳴らす**：
  - 試聴・入力中 → `/desk` が再生
  - 完成時・ギャラリーからの再生 → `/display` が再生（`/desk` の再生バーは `/display` の再生位置を操作・表示する）
- Chrome は `--kiosk` と `--autoplay-policy=no-user-gesture-required` で起動し、ウィンドウ位置で2画面に振り分ける。起動用の `.bat` を用意する。

## 4. 体験フローと状態のルール

```
D1 →(Start) D3 →(これで生成する) D4 → D5
D5 →(言葉を変えて作り直す) D3 ／(同じ言葉でもう一度試行) D4
D5 →(完成したジャケットから再生する) 確定 → D6 ＋ 大型モニターがS2
D6 →(Get It Now) D7a ／(Take It Home) D7b →(終了してホームに戻る) D1
完成前の HOME → D8 →(はい) すべて消去して D1 ／(いいえ) 元の画面へ
D1 のメニュー → D9 → D10 → (Back Gallery) D9
```

- **作り直しは何度でも可。ただし確定（完成）は1人1枚。** 確定ボタンを押したら生成の画面には戻れない。
- **ジャケット No. は確定した時点で付与**（確定順の連番）。作り直しや中止では No. を消費しない。
- **中止（D8で「はい」）は、それまでの入力・生成画像・状態を完全に消去**する（ローカルに残す研究用ログの扱いは下記）。
- **カード No. はジャケット No. とは別の連番**。「Take It Home を選んだ人の順」に、積んだカードの一番上の番号を表示する。
- **Gallery（D9・D10）は待機中（ホーム）からしか入れない。** 体験の途中ではメニューを出さない。
- 確定と同時にギャラリーに追加し、大型モニターはS2（そのジャケットで再生）→ 終了後 S1。
- 一定時間操作がない場合（秒数は config）：D6・D7a・D7b・D9・D10 はホームへ戻る。D3〜D5 は「まだ続けますか？」を出してから戻す（中止扱い）。

## 5. 画像生成

- 送るプロンプト = **固定プロンプト（`prompts/base_prompt.txt`）** ＋ 鑑賞者の入力。固定プロンプトには曲「B7F」のコンセプト・世界観・画風のルールを書く（本文は作者が用意。最初はTODOの雛形でよい）。
- サイズは正方形固定（例：1024×1024）。モデル名・品質・サイズは `config` で変えられるようにする。使えるモデルは OpenAI のドキュメントで確認すること。
- 生成前に入力をチェック：文字数上限、NGワード（`config/ng_words.txt`）、OpenAI のモデレーションAPI。引っかかったら D3 に戻して、やさしい言い回しで書き直しをお願いする。
- 生成に失敗したら、エラー画面ではなく D4 上で「もう一度試す／言葉を変える」を出す。API障害・回線断が続く場合のために、**事前生成した作例ジャケットで体験を続けられる予備モード**を config で切り替えられるようにする（研究データには予備モードであることを記録）。
- 生成時間を毎回記録し、D4 の「完成まであと 00 秒」は直近の平均から出す。
- **タイトル（曲名「B7F」）はAIに描かせる**（決定）。固定プロンプトで「ジャケット内に曲名 B7F を必ず1回だけ入れる」ことを指示し、書体・位置・大きさは鑑賞者の入力に指定があればそれに従い、なければAIに任せる。
  - 文字が崩れる・入らないことがあるため、鑑賞者が D5 で「同じ言葉でもう一度試行」できることを前提にする。
  - 念のため `config` に `title_mode: "ai" | "overlay"` を用意し、`overlay` のときは生成後に Pillow で固定位置に重ねる方式へ切り替えられるようにする（既定は `ai`）。

## 6. 番号・カード・URL

- スマホ用ページのURLは推測されにくいトークンを使う：
  - Get It Now：`https://<GitHubユーザー名>.github.io/<リポジトリ名>/?t=<ランダムなトークン>`（確定時に発行）
  - カード：`https://<GitHubユーザー名>.github.io/<リポジトリ名>/?c=<カード用トークン>`。**カード用トークンは事前に一括発行**し、カード印刷用のCSV（カード No.、トークン、URL）と QR画像を出力するスクリプト（`tools/make_cards.py`）を用意する。
- カードを選んだときに、`カード No. ⇔ カードトークン ⇔ ジャケット` を Supabase でひも付ける。ひも付け前のカードは M2 を表示。
- 表示桁数（`No.0001` など）は config。

## 7. 研究用の記録

ローカル SQLite と Supabase の両方に保存（Supabase への送信に失敗したらローカルに溜めて再送）。page_views はスマホ用ページから Supabase に直接書き込む。

- **covers**：jacket_no、確定日時、入力文（確定版）、作り直し回数、各回の入力文と生成時間、持ち帰り方法（get_it_now / take_it_home）、card_no、token、予備モードかどうか
- **sessions**：開始・中止・確定の日時（中止した回は入力文を残さず、「中止された」事実と時間だけを残す）
- **gallery_plays**：ギャラリーで再生されたジャケットと、再生位置・お気に入りポイントの操作
- **page_views**：スマホ用ページへのアクセス（token または card、日時）。再訪の分析に使う
- **page_events**：スマホ用ページ内の操作（MP3ダウンロード、公式ジャケットのダウンロード、MVリンクのクリック、自分と公式のジャケットの比較表示）。公式公開の前後で再訪や行動がどう変わるかを見る
- 個人を特定する情報（IP アドレスの保存など）は記録しない。

## 8. スタッフ用・運用

- `/admin`（展示PCのlocalhostのみ）：ギャラリーからの非表示、状態のリセット、生成の予備モード切替、カード残数、当日の件数。
- 起動手順を `README.md` に（Flask 起動 → Chrome 2ウィンドウを起動する `.bat`）。PC再起動後に一発で戻せること。
- APIキーなどの秘密情報は環境変数かローカルの設定ファイル（Git管理外）から読む。コードに直接書かない。

## 9. 進め方（フェーズ）

1. **画面とフローの骨組み**：Flask + `/desk` `/display` の全画面を、生成をダミー画像に置き換えて遷移・状態同期・音声の切り替えまで動かす
2. **画像生成**：OpenAI 接続、固定プロンプト、入力チェック、生成時間の計測、タイトルの扱い
3. **確定・番号・記録**：No. 付与、SQLite 記録、ギャラリー追加、S2 の CD 回転アニメーション
4. **Supabase と GitHub Pages**：テーブルとRLSの作成SQL、アップロード、トークン、M1・M2、カード発行スクリプト、アクセス記録、休止対策
5. **運用**：予備モード、無操作タイムアウト、/admin、起動 `.bat`、README

## 10. Supabase と GitHub Pages の構成（決定）

### Supabase（無料プラン）
- 展示PCからは **REST API を httpx で直接呼ぶ**（supabase-py などの追加ライブラリは使わない）。
  - Storage：`POST {SUPABASE_URL}/storage/v1/object/covers/<ファイル名>`（画像アップロード）
  - DB：`{SUPABASE_URL}/rest/v1/<テーブル>`（PostgREST）
- 鍵の使い分け：
  - **service_role キー**：展示PCだけに置く（環境変数／Git管理外の設定ファイル）。アップロードと covers・cards の書き込みに使う
  - **anon（公開）キー**：スマホ用ページに埋め込む。**RLS で許可した操作しかできない**ようにする
- バケット `covers`：公開読み取り（ジャケット画像のURLをそのまま `<img>` で表示するため）。書き込みは service_role のみ
- テーブル（作成用のSQLを `supabase/schema.sql` に用意すること）：
  - `covers`：jacket_no、token（unique）、image_url、prompt、confirmed_at、hidden（ギャラリー非表示フラグ）
  - `cards`：card_no、card_token（unique）、jacket_no（ひも付け前は null）、linked_at
  - `page_views`：token または card_token、viewed_at、種別（get_it_now / card）
  - `page_events`：token または card_token、event（mp3_download / official_download / mv_click / compare_view）、created_at
- RLS：
  - `covers`：anon は hidden=false の行の公開用カラム（jacket_no、image_url、prompt、confirmed_at）だけ読める
  - `cards`：anon は card_token を指定した1行だけ読める（一覧取得はさせない。必要なら RPC 関数で「トークン → 表示用データ」を返す形にする）
  - `page_views`・`page_events`：anon は書き込み（insert）のみ。読み取りは不可
  - 研究用の詳細データ（作り直し回数・各回の入力など）は Supabase に置かず、展示PCのローカル SQLite に残す
- **休止対策**：無料プランは1週間アクセスがないと休止する。GitHub Actions で数日おきに Supabase へ軽いリクエストを送るワークフロー（`.github/workflows/keepalive.yml`）を用意する。公開期間は少なくとも 2026/12/18 まで

### GitHub Pages
- スマホ用ページ用のリポジトリ（または `docs/` フォルダ）に、`index.html`・CSS・JS・楽曲MP3・フォントを置く。
- `index.html` は1枚で、URLのクエリで表示を切り替える：
  - `?t=<token>` → covers を読んで M1
  - `?c=<card_token>` → cards を読み、ひも付け済みなら M1、未ひも付けなら M2
  - 該当なし・エラー → やさしいエラー表示
- 表示時に page_views へ1件書き込む（再訪の記録）。ボタン操作は page_events に書き込む。
- 公式ジャケット画像（公開日以降に表示）もGitHub Pagesに置く。MVはYouTubeへの外部リンク（クリックを記録してから遷移）。
- **Get It Now と Take It Home のどちらで来た人にも、公開日の告知を同じように見せる**（比較の条件をそろえるため）。D7a・D7b の画面とカードにも公開日を記載する。
- **楽曲MP3はGitHub Pagesに置く**（同じサイトから配信することで iPhone でも `Download (MP3)` が動き、Supabase の通信量も使わない）。
- ジャケット画像は `<img src="Supabaseの公開URL">` で表示（長押しで保存できること）。
