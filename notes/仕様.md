## 4. 状態と音声のルール（実装）

- サーバーの状態：`desk`（画面・モーダル）、`session`（作成中の入力・試行）、`audio`、`display`、確定済みジャケット一覧。
- 音声は `audio.owner`（`desk` / `display` / なし）の画面だけが鳴らす。鳴らしている画面が再生位置をサーバーへ報告し、もう一方はそれを表示・操作する。
  - D3〜D5：desk が再生。確定時：display がサビ区間を再生 → 終了で S1。D10：display が再生し、desk の再生バーで操作。
- 確定時に No. を付与（確定順）。カード No. は Take It Home を選んだ順で別連番。
- 中止（D8「はい」）：入力・生成画像・状態を消去。

## 4b. 画像生成（フェーズ2）

- 送るプロンプト ＝ `prompts/base_prompt.txt` ＋（title_mode が `ai` のとき）`prompts/title_ai.txt` ＋「鑑賞者の言葉：」＋ 入力。
- 出力は jpeg・正方形（`openai.size`、既定 1024×1024）。モデル・品質・サイズ・圧縮率は `config` の `openai` で変更。
- **使用モデル：`gpt-image-2.6-sunburst`（決定）**。品質（quality）は未確定（仮 `medium`）。OpenAI のドキュメントにこちらの環境から接続できなかったため、`tools/test_generate.py` で速度と仕上がりを比べて決める。openai ライブラリの記載では `gpt-image-1` は 2026/10/23 に提供終了。比較の候補は `gpt-image-2`、`gpt-image-2.5-sunburst`／`-flare`、`gpt-image-2.6-sunburst`／`-flare`（ライブラリに「対応モデル」として記載。「gpt-image-2.6」単体の名前は無い）。
- 入力チェック：
  1. 文字数（`input.max_chars`）・NGワード（`config/ng_words.txt`。全角半角・大文字小文字を区別しない部分一致）→ D3 のまま書き直しのお願い
  2. OpenAI モデレーションAPI（`omni-moderation-latest`）→ 引っかかったら D4 から D3 に戻してお願いを表示（入力は残す）
  3. 画像生成API側で安全上の理由で断られた場合も 2 と同じ扱い
- お願いの文言：「ごめんなさい、その言葉ではジャケットをつくれませんでした。別の言い方で書きなおしてみてください。」
- API障害・回線断・タイムアウト（120秒）→ D4 で「もう一度試す／言葉を変える」。
- 生成時間は成功時に毎回記録し、D4 の残り秒数は直近5回の平均から出す（記録が無いときは 30 秒）。
- タイトル：`title_mode: "ai"`（既定・決定）。`"overlay"` にすると AI への曲名の指示を外し、生成後に Pillow で固定位置（`generation.title_overlay`）に曲名を重ねる。
- API キー：環境変数 `OPENAI_API_KEY` か `config/secrets.json`（Git管理外）。`backend: "auto"` はキーがあれば OpenAI、無ければダミー。
- 予備モード（作例ジャケットで体験を続ける）はフェーズ5。
- **D4 の最低表示時間：5秒（作者決定）**。生成が早く終わっても「Now Pressing...」を5秒は見せる（`generation.min_pressing_sec`）。残り秒数の表示も5秒以上になる。
- **鑑賞者の言葉はジャケットに文字として書き込まない（作者決定）**。`prompts/input_rule.txt` で指示（色・景色・雰囲気として表現する）。ダミー画像にも入力文を描かない。

## 4c. 確定・番号・記録（フェーズ3）

- 保存先：ローカル SQLite `data/mycover.db`（Git管理外）。生成画像は `data/images/`。
- 起動時に確定済みジャケットを読み込み、ギャラリー・No.・カード No. の続きから再開する。確定していない画像（途中終了の残り）は起動時に削除。
- 表：`covers`（確定）、`cover_attempts`（各回の入力文と生成時間）、`sessions`（開始・終了・結果）、`gallery_plays`／`gallery_events`（ギャラリーの再生と操作）。列は `mycover/db.py` を参照。
- 中止した回：`sessions` に開始・終了時刻と `aborted` だけを記録（入力文・回数は残さない）。生成画像も削除。
- `covers.synced`（Supabase 送信済み）はフェーズ4、`backup_mode`・`hidden` はフェーズ5で使う。
- 書き出し：`export_csv.bat`（UTF-8 BOM 付き CSV、Excel で開ける）。

## 4d. Supabase と GitHub Pages（フェーズ4）

- **No. は4桁、カードは100枚（No.0001〜0100）（作者決定）**。100枚を使い切ると Take It Home は押せない（「カードの配布は終了しました」）。
- 展示PC → Supabase：確定直後と Take It Home 選択直後に送信（`mycover/supabase.py`）。画像は Storage `covers/<token>.jpg`、`covers` は jacket_no で upsert、カードは `cards` の jacket_no・linked_at を更新。失敗時は SQLite の `synced`／`card_synced` で管理し、30秒ごとに再送。
- 秘密キー：`config/secrets.json` の `supabase_secret_key`（`set_supabase_key.bat` で保存）か環境変数 `SUPABASE_SECRET_KEY`。新形式（sb_secret_）は apikey ヘッダーだけ、旧形式（JWT）は Authorization にも付ける。
- カード：`make_cards.bat`（`tools/make_cards.py`）でトークン（16文字）を発行し、`data/cards/cards.csv` と QR 画像を出力、Supabase に登録。既存トークンは変更しない（手元／Supabase から読み込み、食い違えば中止）。
- QR の URL：Get It Now は `mobile.base_url`（`https://usagi-15.github.io/mycover/?t=`）、カードは `mobile.public_url`（`…/?c=`）。
- スマホ用ページ：`mobile/`（index.html・style.css・app.js・config.js）。`?t=` は RPC `get_cover_by_token`、`?c=` は RPC `get_card`。未登録の直後は3秒ごとに最大12回読み直す。表示時に `page_views` に1件記録（kind・token または card_token のみ）。ジャケットは `<img>`（長押し保存）。MP3 は同じサイトの `B7F.mp3`（無い間は「準備中」）。
- 開発中は Flask の `/m/` でも同じページを配信（`mobile/` をそのまま返す）。
- 休止対策：`mobile/.github/workflows/keepalive.yml`（GitHub Pages 用リポジトリに置く。2日おきに公開キーで RPC を呼ぶ）。

## 4e. 特設エリア M3・page_events（改訂版の指示書）

- M1・M2 の下に特設エリア（Special）。**Get It Now・Take It Home（未ひも付けのカードも）のどちらで来た人にも同じ告知**を出す。
- 公式ジャケット：公開日前は日付とカウントダウン、公開後は「あなた盤」と「公式盤」を並べて表示し、公式ジャケットの保存ボタン。未ひも付けのカードは公式盤だけ。公式画像は GitHub Pages の `official.jpg`（無いあいだは「準備中」）。
- MV：公開日前は日付とカウントダウン、公開後（かつ URL 設定済み）は「MV を見る（YouTube）」。クリックを記録してから遷移。
- 公開日は `mobile/config.js` の `release`。null のあいだは「近日公開」。日付は端末の設定によらず日本時間で表示。
- `page_events`（event・token または card_token・created_at）。anon は insert のみ。
- D7a・D7b にも公開日を表示（`config/config.json` の `release`）。

## 4f. 運用（フェーズ5）

- **無操作タイムアウト：60秒、「まだ続けますか？」20秒（作者決定）**。対象は D2・D6・D7a・D7b・D9・D10（ホームへ。D2 は指示書に無いが待機中の画面なので含めた）と D3〜D5（確認→中止）。生成中は数えない。判定は机の画面（キーボード・マウスの操作）で行う。
- 中止の理由を `sessions.abort_reason` に記録：`home`（D8）／`timeout`（無操作）／`admin`（/admin のリセット）。
- **予備モード**：/admin で切り替え（`data/runtime.json` に保存し、再起動後も維持）。生成せず `static/backup/` の画像（無ければ作成例の画像）からランダムに1枚。モデレーションAPIも使わない（文字数・NGワードは確認）。`covers.backup_mode` に記録。予備モードの生成時間は残り秒数の推定に使わない。
- **/admin**：localhost（127.0.0.1・::1）からのみ。状態のリセット（体験を中止扱いにしてホーム・S1 へ。記録は消さない）、予備モード、非表示（Supabase の hidden も送り直す）、カード残数、当日の件数、クラウド送信状況。**テストデータの片付けは入れない（作者決定）**。
- **本番用の起動 `start_exhibit.bat`（作者決定：本番用だけ作る）**：サーバーを最小化で起動して待ち、Chrome を別プロファイルで2つキオスク表示（位置は bat 内の変数）。

## 5. 実装上の判断（指示書に明記がなく、仮に決めたもの）

確認が取れたら更新すること。

1. **お気に入りポイント**（D10「お気に入りポイントから再生」）：定義が指示書にないため、仮に「これで生成する」を押した時点の D3 の再生位置を記録している。
2. **メニューを開ける画面**：指示書は「ホーム（待機中）でのみ」。D9（Gallery）と D2（About）にもハンバーガーがあるため（PDF p.9）、待機中の画面 D1・D2・D9 で開けるようにし、D1 以外では「Home」項目を追加した。体験中（D3〜D7）と D10 では出さない。
3. **D7a・D7b の HOME**：PDF に無いため表示しない（「終了してホームに戻る」で戻る）。
4. **サビ未設定時の S2**：0秒から `s2_fallback_seconds`（30秒）だけ再生する。
5. **D10 で曲が最後まで再生されたとき**：停止して位置を先頭に戻し、S2 のまま待つ。
6. **S1 の「新しいジャケットを目立たせる」**：確定から `highlight_new_sec`（600秒）の間、白枠と「NEW」を付け、各段に繰り返し差し込む。
7. **D1 のキービジュアル**：画像ファイルが無いため CSS のぼかしグラデーションで仮置き。
