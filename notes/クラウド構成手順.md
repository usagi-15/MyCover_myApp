# クラウド構成手順（Supabase ＋ GitHub Pages）

> 実装指示書 10章の構成を、作者が手を動かして準備するための手順。
> アプリ側のコード（アップロード・スマホ用ページ・カード発行・休止対策）はフェーズ4で実装する。
> この手順で作ったアカウントや URL・キーを、フェーズ4で設定ファイルに入れて使う。
>
> 注意：Supabase・GitHub の画面の名前や配置は変わることがある。見つからないときは近い名前の項目を探すか、スクリーンショットを共有してください。

最終更新：2026-11-24（フェーズ4の手順を追加：6章）

---

## 0. 全体像

```
展示PC ──(service_role / secret キー)──▶ Supabase
                                          ├─ Storage：covers バケット（ジャケット画像・公開読み取り）
                                          └─ DB：covers / cards / page_views
鑑賞者のスマホ ──▶ GitHub Pages（index.html・MP3・フォント）
                    └─(anon / publishable キー)──▶ Supabase（RLS で許可した操作だけ）
```

| もの | 置き場所 | 公開してよいか |
| --- | --- | --- |
| Project URL | 展示PC・スマホ用ページ | よい |
| anon（publishable）キー | スマホ用ページに埋め込む | よい（RLS で守る前提） |
| service_role（secret）キー | **展示PCだけ**（Git管理外の設定ファイル） | **絶対に公開しない**（チャットにも貼らない） |
| DB パスワード | パスワード管理アプリなど | 公開しない（アプリでは使わない） |

### 先に決めること：スマホ用ページの URL

カードには URL と QR が印刷されるため、**カードの印刷前に GitHub Pages の URL を確定**させる必要がある。
URL は `https://<GitHubユーザー名>.github.io/<リポジトリ名>/` になる。リポジトリ名は短く、後で変えないものにする（例：`mycover`）。

## 1. Supabase の準備

### 1-1. プロジェクトを作る

1. https://supabase.com にアクセスし、「Start your project」からサインアップ（GitHub アカウントでログインできる）。
2. 「New project」を押す。
   - Organization：個人用のもの（無ければ作る。プランは **Free**）
   - Project name：`mycover` など
   - Database Password：「Generate a password」で作り、パスワード管理アプリなどに保存
   - Region：**Northeast Asia (Tokyo)**
3. 「Create new project」。準備に数分かかる。

### 1-2. テーブル・権限・バケットを作る

1. 左メニューの **SQL Editor** を開き、「New query」。
2. このリポジトリの `supabase/schema.sql` の中身を全部貼り付けて **Run**。
   - 「Success. No rows returned」と出れば成功。何度実行しても壊れないようになっている。
3. 確認：
   - **Table Editor** に `covers`・`cards`・`page_views` の3つがあり、それぞれ「RLS enabled」になっている
   - **Storage** に `covers` バケットがあり、「Public」になっている

`schema.sql` で設定している内容（実装指示書 10章の RLS どおり）：

| テーブル | スマホ用ページ（anon）ができること |
| --- | --- |
| covers | 非表示でない行の公開用カラム（jacket_no, image_url, prompt, confirmed_at）だけ読める。token は読めない |
| cards | 直接は読めない。関数 `get_card(カードトークン)` で1件だけ取得できる |
| page_views | 書き込み（insert）だけ。読み取りは不可 |
| Storage covers | 画像の読み取りだけ（書き込みは展示PCの service_role のみ） |

Get It Now の URL（`?t=`）は関数 `get_cover_by_token(トークン)` で1件だけ取得する。
※ この SQL は、Supabase と同じ名前のロールを作ったローカルの PostgreSQL で動作を確認済み。本物の Supabase ではまだ試していないので、エラーが出たら内容を共有してください。

### 1-3. URL とキーを控える

左下の **Project Settings**（歯車）→ **API Keys**（または「Data API」）を開く。

- **Project URL**：`https://xxxxxxxx.supabase.co`
- **公開キー**：`publishable` キー（`sb_publishable_...`）、または「Legacy API keys」タブの `anon` キー
- **秘密キー**：`secret` キー（`sb_secret_...`）、または「Legacy API keys」タブの `service_role` キー

新しい形式（publishable / secret）と旧形式（anon / service_role）のどちらを使うかは、フェーズ4で展示PCからのアップロードを試して決める。両方控えておけばよい。

### 1-3b. 動作確認（schema.sql が反映されているか）

ブラウザのアドレス欄に次を貼り付けて開く（公開キーなので問題ない）。

```
https://hasykewktdnsqgrnzgij.supabase.co/rest/v1/rpc/get_card?p_card_token=test&apikey=sb_publishable_tV56DfmPw7fX5CfcCKNEyA_1yI9Dxwm
```

| 表示 | 意味 |
| --- | --- |
| `[]` | 成功（関数があり、test というカードは無いので空） |
| `Could not find the function ...` など | schema.sql がまだ実行されていない、または途中で失敗している |
| `Invalid API key` など | キーの貼り付けミス |

### 1-4. 秘密キーの置き場所（展示PCのみ）

フェーズ4で、展示PC上の `config/secrets.json`（Git 管理外。`.gitignore` 済み）か環境変数に入れる形にする。
**秘密キーは GitHub・チャット・スマホ用ページのどこにも書かない。**

### 1-5. 無料プランの注意

- **1週間アクセスがないとプロジェクトが休止する**。フェーズ4で GitHub Actions のワークフロー（`.github/workflows/keepalive.yml`）を作り、数日おきに軽いリクエストを送る。公開期間は少なくとも 2026/12/18 まで。
- ストレージ容量・転送量には上限がある。ダッシュボードの **Usage** で確認できる。画像は jpeg で保存して容量を抑える。

## 2. GitHub Pages の準備

### 2-1. スマホ用ページ専用の公開リポジトリを作る（おすすめ）

- 無料プランの GitHub Pages は **公開（Public）リポジトリ**でしか使えない。
- このリポジトリ（MyCover_myApp）には制作メモや展示PC用のコードも入っているため、**スマホ用ページだけを入れる別の公開リポジトリ**を作るのがおすすめ。
  - 代わりにこのリポジトリの `docs/` フォルダを使う方法もあるが、その場合はこのリポジトリ全体を公開することになる。

手順：

1. GitHub 右上の「＋」→「New repository」。
2. Repository name：`mycover` など（**URL になるので短く、後で変えない名前**）。
3. **Public** を選び、「Add a README file」にチェックを入れて「Create repository」。

### 2-2. Pages を有効にする

1. 2-1 で作ったリポジトリ（例：`mycover`）のページを開く（`https://github.com/<ユーザー名>/mycover`）。
2. リポジトリ名の下に並ぶタブ（Code / Issues / Pull requests / Actions …）の**右端にある「⚙ Settings」**をクリック。
   - 見当たらないときは、タブ列の右端の「…」の中にある。ウィンドウを広げると表示されることもある。
3. 左側のメニューを下へスクロールし、「Code and automation」の中にある **「Pages」**をクリック。
4. 「Build and deployment」という見出しの下を設定する。
   - **Source**：プルダウンが「Deploy from a branch」になっていることを確認（違えば選ぶ）
   - **Branch**：その下の「None」と書かれたボタンをクリック → **`main`** を選ぶ
   - 右隣のフォルダのボタンは **`/ (root)`** のまま
   - **「Save」**ボタンを押す
5. 1〜2分待ってから、ページを再読み込みする。上部に
   **「Your site is live at https://<ユーザー名>.github.io/mycover/」** と出れば公開完了。
   「Visit site」を押すと、最初は README の内容が表示される。

うまくいかないとき：

| 症状 | 原因と対処 |
| --- | --- |
| Branch のボタンに `main` が出てこない | リポジトリが空。2-1 で「Add a README file」にチェックを入れずに作った。Code タブで「Add file」→「Create new file」で何かファイルを作れば出てくる |
| Pages の画面に「Upgrade」などと出て設定できない | リポジトリが Private になっている。Settings の一番下「Danger Zone」→「Change visibility」で Public にする |
| 「Your site is live」がなかなか出ない | 上部タブの「Actions」を開き、「pages build and deployment」に緑のチェックが付くまで待つ（数分）。赤い × のときは画面を共有してください |

### 2-3. 置くファイル（フェーズ4で用意）

```
index.html      スマホ用ページ（?t= / ?c= で M1・M2 を切り替え）
style.css
app.js          Project URL と publishable キーをここに書く（公開してよい）
B7F.mp3         楽曲（Download (MP3) 用。同じサイトから配信することで iPhone でも保存できる）
fonts/          フォントファイル
```

- MP3 は誰でもダウンロードできる状態になる（作品の意図どおり）。
- GitHub は 1ファイル 100MB まで（MP3 なら通常問題なし）。

## 4. フェーズ4でやること（参考）

1. 展示PC → Supabase：ジャケット画像のアップロード、covers・cards の書き込み（httpx で REST を直接呼ぶ）
2. スマホ用ページ（M1・M2）の作成と、page_views への記録
   - anon は page_views を読めないため、書き込みは `Prefer: return=minimal` で送る
3. `tools/make_cards.py`：カードトークンの一括発行、印刷用 CSV と QR 画像の出力
4. `.github/workflows/keepalive.yml`：休止対策
5. 開発中は、スマホ用ページを展示PCの Flask からも開けるようにし、同じ Wi-Fi のスマホで確認する

## 5. スケジュールの目安

展示は 2026/12/3 から。カードの印刷に間に合わせるため、**GitHub Pages の URL の確定 → カード発行スクリプト → 印刷**を早めに進める。

## 6. フェーズ4の作業（展示PC・開発PCで行う）

ここからは、フェーズ4で用意したファイルを使う。最新のコードを取り直してから行う（`data` フォルダと `config/secrets.json` は前のフォルダからコピー）。

### 6-1. Supabase の秘密キーを保存する：`set_supabase_key.bat`

1. Supabase の **Project Settings → API Keys** を開き、**Secret keys** の欄でキーを表示してコピーする（`sb_secret_` で始まる）。
   - 無いときは「Create new secret key」で作る。旧形式（Legacy API keys）の `service_role` キーでもよい。
2. `set_supabase_key.bat` をダブルクリック → 右クリックを **1回だけ** 押して貼り付け → Enter。
3. 「データベース：OK」「Storage：OK」「保存しました」と出れば完了。キーは `config/secrets.json`（GitHub に上がらない）に保存される。

**秘密キーはチャット・GitHub・スマホ用ページに絶対に書かない。**

### 6-2. カードを発行する：`make_cards.bat`

1. 6-1 のあとに `make_cards.bat` をダブルクリック。
2. 「カード 100 枚（新しく発行 100 枚）」「Supabase の cards に登録しました」と出て、`data\cards` フォルダが開く。
   - `cards.csv`：カード No.（1〜100）、表示用 No.（No.0001〜）、トークン、URL、QR 画像のファイル名（Excel で開ける）
   - `qr\card_0001.png` 〜 `card_0100.png`：各カードの QR 画像
3. この CSV と QR 画像を使ってカードをデザイン・印刷する（カードには No. と QR、必要なら URL を載せる）。
4. **`data\cards` フォルダを USB メモリなどにバックアップする。**

何度実行しても、既にあるカードのトークンは変わらない（手元か Supabase から読み込む）。手元と Supabase で食い違うときは何も変えずに止まる。

カードは **No.0001 から順に、山の一番上から配る**（Take It Home を選んだ順に No. が振られ、画面に「No.〇〇 のカードをお取りください」と出る）。100枚を使い切ると Take It Home は押せなくなる。

### 6-3. スマホ用ページを公開する

このリポジトリの **`mobile` フォルダの中身**を、GitHub Pages 用のリポジトリ `usagi-15/mycover` に置く。

置くもの（`mobile` フォルダの中身をそのまま）：

```
index.html / style.css / app.js / config.js / README.md
fonts/                     フォントファイル（未配置）
.github/workflows/keepalive.yml   Supabase の休止対策
B7F.mp3                    ★楽曲。作者が用意して同じ場所に置く（まだ無い）
```

ブラウザでの置き方：

1. https://github.com/usagi-15/mycover を開く → 「**Add file**」→「**Upload files**」。
2. `mobile` フォルダの**中身**（フォルダごとではなく、中のファイルとフォルダ）をすべて選んでドラッグ＆ドロップ。
3. 下の「**Commit changes**」を押す。
4. 1〜2分後、`https://usagi-15.github.io/mycover/` を開き、「会場の QR コードやカードからアクセスしてください」と出れば公開されている。

確認：

- 会場で Get It Now を選んで QR を読むと、ジャケットと曲のページ（M1）が開く。
- `data\cards\cards.csv` の URL を開くと、まだ使っていないカードは「まだジャケットがひもづいていません」（M2）。
- 楽曲MP3を置くまでは、再生とダウンロードが「準備中」になる。

### 6-4. 休止対策（keepalive）の確認

1. `usagi-15/mycover` の **Actions** タブを開く。初めてのときは「I understand my workflows, go ahead and enable them」を押して有効にする。
2. 左の「keepalive」→「**Run workflow**」で手動実行し、緑のチェックが付けば OK。以後は2日おきに自動で動く。
3. 公開期間（少なくとも 2026/12/18）が終わったら、このワークフローは無効にしてよい。

### 6-5. 送信の仕組み（参考）

- 確定すると、展示PCがすぐにジャケット画像と情報を Supabase に送る。Take It Home ならカードとのひも付けも送る。
- 回線が切れていても展示は続けられる。送れなかったものは展示PC内に記録され、30秒ごとに再送される（サーバーの黒い窓に「送信に失敗」「送信しました」と出る）。
- スマホ用ページは、確定直後でまだ届いていないときは「準備しています」と表示して数秒ごとに読み直す。
