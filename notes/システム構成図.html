『My Cover』のシステム構成

展示PCの中の Flask サーバーが、2つの画面と体験の状態をまとめて管理し、画像の生成は OpenAI に、持ち帰り用のデータは Supabase に送ります。鑑賞者のスマホは GitHub Pages のページから Supabase を読みに行くので、展示PCに直接つながることはありません。

体験の流れと、そのときシステムで起きること

画面鑑賞者の操作システムで起きること音を鳴らす画面
D1 ホームStart を押す体験（session）を開始し、開始時刻を SQLite に記録なし
D3 聴く・言葉にする曲を聴きながら言葉を入力文字数と NG ワードをその場で確認机のモニター
D4 生成する「これで生成する」OpenAI のモデレーション → 画像生成。最低5秒は Now Pressing を表示。断られたら D3 に戻して書き直しをお願い机のモニター
D5 完成（確認）作り直す／もう一度試す各回の入力と生成時間をメモリに保持（確定まで保存しない）机のモニター
D5 → D6 確定「完成したジャケットから再生する」No. を付けて SQLite に保存 → 大型モニターが S2 でサビを再生 → すぐに Supabase へ画像と情報を送信大型モニター
D7a Get It NowQR をスマホで読むスマホ用ページがトークンでジャケットを1件取得。届いていなければ3秒ごとに読み直す大型モニター
D7b Take It Homeカードを取るカード No. を割り当て、Supabase でカードとジャケットをひも付け（100枚まで）大型モニター
D8 中止完成前に HOME →「はい」入力と生成画像を消去。記録には「中止」と時刻だけを残すなし
D9 → D10 Galleryジャケットを選んで再生・操作大型モニターが S2 で再生し、机の再生バーがそれを操作。再生と操作を記録大型モニター

音は常に1つの画面だけが鳴らします。鳴らしている画面が再生位置をサーバーに報告し、もう一方の画面はそれを表示・操作します。

データの置き場所

場所中身書く／読む
展示PC data/mycover.db確定したジャケット、各回の入力と生成時間、体験の開始・中止・確定、ギャラリーの操作Flask が書く。export_csv で CSV に
展示PC data/images/確定したジャケット画像Flask が書き、2つの画面が表示
展示PC data/cards/カード100枚のトークン・URL・QR 画像make_cards が作る。要バックアップ
Supabase Storageジャケット画像（公開読み取り）展示PCが書き、スマホが表示
Supabase DBcovers（公開用の列）、cards、page_views展示PCが書き、スマホは関数経由で1件だけ読む
GitHub Pagesスマホ用ページ、楽曲 MP3作者が置く

作り直し回数や各回の入力など研究用の細かい記録は、クラウドに送らず展示PCだけに残します。IP アドレスなど個人を特定する情報は記録しません。

鍵（キー）の扱い

キー置き場所できること
OpenAI API キー展示PC config/secrets.json画像生成・モデレーション（利用料金がかかる）
Supabase 秘密キー展示PC config/secrets.json画像のアップロード、covers・cards の書き込み
Supabase 公開キースマホ用ページ config.js非表示でないジャケットの公開列を読む、関数で1件取得、page_views に書く

secrets.json は GitHub に上がりません。秘密キーと OpenAI のキーは、チャットやページに書かないこと。

役割ファイル
